## What this is

Reinforcement learning policies deployed on physical robots will face actuator degradation,
yet standard agents carry no explicit mechanism for noticing that their own actuators have
changed. This project asks whether a trained agent can detect an actuator fault using **only
the quantities it already computes** — value estimates, policy entropy and temporal-difference
errors — with no external monitoring model.

**Headline finding.** Self-detection is achievable but strongly architecture-dependent, and
fault tolerance trades off against fault detectability: the agent that copes best with a
failing engine is the one least able to notice it. Domain randomisation — normally a
sim-to-real technique — turns out to be a practical enabler of fault self-awareness, not by
creating the detection signal but by calibrating the reference distribution against which
deviations are judged.

## Research questions

| | Question |
|---|---|
| **RQ1** | Can an agent detect a change in its own actuator response from internal signals alone? |
| **RQ2** | Does a relationship exist between tolerating a fault and detecting it? |
| **RQ3** | Does domain randomisation affect fault detectability, and by what mechanism? |
| **RQ4** | Can internal signals go beyond detection to *attribution* — self versus world? |

## Agents

| Agent | Environment | Action space | Network | Budget |
|---|---|---|---|---|
| PPO | LunarLander-v3 | Discrete(4) | MLP 64×64 | 1.0 M steps |
| SAC | LunarLanderContinuous-v3 | Box(2,) | MLP 400×300 | 0.25 M steps |
| PPO+DR | LunarLander-v3 + domain randomisation | Discrete(4) | MLP 128×128 | 1.4 M steps |
| Q-learning | LunarLander-v3 | Discrete(4) | Tabular, 10 bins/dim | 0.5 M steps |

All agents trained on five seeds (0–4).

## Reproducing

```bash
git clone https://github.com/raghuramantm/can-an-agent-tell-it-is-broken.git
cd can-an-agent-tell-it-is-broken
python -m venv venv && source venv/bin/activate
pip install -r requirements.txt
jupyter lab notebooks/
```

Notebooks are ordered and assume the preceding ones have run. Trained policies in `models/`
let the analysis notebooks (NB06 onward) run without retraining.

Training was performed on Apple Silicon: vectorised environment stepping on CPU, network
updates on the Metal Performance Shaders (`mps`) backend.

## Notes on the published artefacts

- `models/` contains the **best** policy per seed. Intermediate training checkpoints are
  excluded to keep the repository small; convergence evidence is in the paper's Appendix A.
- Q-learning policies are published as discretised Q-tables (`.npz`).
- Figures in the paper are generated by the notebooks that produce the underlying results.
